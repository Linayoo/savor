# 0006: Run the app as a development build instead of Expo Go

Status: accepted
Date: 2026-11-02

## Context

Spec 005 adds sign-in with Cognito (ADR 0004). The app client allows only SRP sign-in and token refresh.
Amplify Auth v6, the chosen auth library, computes the SRP math in its own native module (`@aws-amplify/react-native`) and needs `react-native-get-random-values` linked natively.
Expo Go only contains the native modules of the Expo SDK, so Amplify v6 doesn't run in it; Amplify's docs say Expo Go is not supported in v6 and point to development builds.

Until now the app ran in Expo Go on the phone and the simulator.

## Options considered

1. Amplify Auth v6 in a development build
2. `amazon-cognito-identity-js`, which does SRP in JavaScript and runs in Expo Go, but is superseded by Amplify v6 and no longer developed
3. Own SRP implementation against Cognito's API, which means maintaining auth crypto
4. Cognito's hosted sign-in page through `expo-auth-session`, which runs in Expo Go but replaces the in-app account screens and needs OAuth flows, a domain and callback URLs in Terraform

## Decision

Option 1. The app runs as a development build that includes `expo-dev-client`.

- Continuous Native Generation: `ios/` and `android/` are generated by `expo prebuild` (or `expo run:ios`) and stay gitignored. Native settings live in `app.json` and config plugins, never in edited native files.
- Bundle identifier and Android package: `com.linayoo.savor`.
- Tokens are stored with `expo-secure-store` (the iOS Keychain and Android Keystore), not AsyncStorage.

## Consequences

- Daily work: `npx expo run:ios` builds and installs the app once, which needs Xcode on the Mac. After that, `pnpm --filter @savor/mobile start` serves JavaScript as before, with fast refresh. A new build is only needed when a native package or the native config changes.
- The iOS simulator needs no Apple account. Several simulators can run the same build, which is how two devices are tested.
- A physical iPhone needs a signed build:
  - A free Apple ID works through Xcode's personal team, but the app stops opening after 7 days and has to be installed again, with a limit on how many apps can be signed this way.
  - The paid Apple Developer Program (99 USD per year) removes the 7-day limit and is needed for TestFlight anyway (M5).
  - The phone is optional for development; the simulators cover the manual checks.
- Moments kept in Expo Go don't carry over. Expo Go and the development build are different apps with separate storage, so the SQLite database in Expo Go stays there. Moments that matter must be re-kept in the development build, or moved before switching.
- CI doesn't need Xcode: typecheck, lint, tests and `expo export --platform ios` only bundle JavaScript, so they keep running on Linux. Native builds happen locally until M5 moves them to EAS.
- Amplify's native module uses React Native's interop layer for older modules; if a future React Native version drops that layer, Amplify must have caught up first.
